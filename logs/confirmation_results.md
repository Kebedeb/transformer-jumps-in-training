Ambiguities: (i) whether “qualifies” in Partial/Refutes means confirmed-and-specific (A) or confirmed (B); (ii) the rules do not rank labels when more than one condition is met; (iii) “a control reaches 50% accuracy” can be read as reaching 0.5 at any evaluation (Controls section: “never reaches 0.5”) or as staying ≥ 0.5 (deviation 4); (iv) “fails by one seed” and “flips across the sensitivity grid” do not say whether they refer to batch 1, batch 2, any signal, or only signals relevant to a claim; (v) Inconclusive “triggers the extra-seed rule”, but S2 (seeds 6-10) is the extra-seed run itself and the pre-registration does not say what follows after it. No reading is chosen here.

## 10. Implementation choices

1. Batch membership comes from `seed` in config.json: 1-5 batch 1, 6-10 batch 2; controls are runs whose directory contains `_ctrl_`, with `experiment_name` mapped to task and type (C1: grokking_ctrl_wd0, icl_ctrl_fixedonly; C2: *_ctrl_shuffle) and seeds 101-103.
2. All onset, lead, qualification, precursor and shared-candidate computations call the functions of precursor_analysis.py (`analyse`, `verdicts`, `cross_task`) with its pre-registered defaults; batch 1, batch 2 and controls are passed separately so each batch is analysed on its own.
3. t50 = stays-above 0.5 on metrics.csv (`stays_above_step` from jump_detection.py). Batch-1 t50 is also checked against logs/run_results.md. For every jump run it is cross-checked against the same metric column in signals.csv; disagreements are listed in section 11 and metrics.csv is used.
4. Controls: validity uses the stays-above rule on metrics.csv (deviation 4). For valid controls the run's “t50” is set to the anchor, so the reference window, onset window, direction and minimum lead all use the anchor. The anchor is the batch-1 mean t50 recomputed from the data (and checked equal to the pre-registered 296/816/7525), snapped to the nearest checkpoint step in the control's signals.csv.
5. Non-specific: counting onsets ≥ 2 in either control type of the task. Induction has only a C2 control. If a control type had fewer than 3 valid seeds, the count is shown out of the valid seeds and the threshold of 2 is unchanged.
6. Confirmed = precursor (pre-registered rule) in batch 1 and in batch 2. The rules do not require the direction to match between batches; the replication table shows whether it does.
7. Section 7 applies the shared-precursor rule to batch-2 directions and batch-2 median normalized leads, as instructed; batch-1 values are shown but not used.
8. Window-limited onsets (deviation 2) are marked WL; their normalized leads are included in medians unchanged (no decision rule is changed).
9. The rise-time comparison (deviation 3) uses t90 − t50 from metrics.csv and is not used for any verdict.
10. Section 8 lists every decision-rule label whose condition is met under each reading; it does not choose between them.
11. No signals, parameters or windows other than the pre-registered ones were run.
